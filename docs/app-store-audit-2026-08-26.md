# Quite Note App Store 拒审后审计（2026-08-26）

## 结论

代码与商店包层面的确定性问题已修复，自动测试通过。用户确认继续后，构建 `1.0.0 (4)` 已于 2026-08-26 上传、关联并重新提交，Apple API 读回状态为 `WAITING_FOR_REVIEW`。干净账号或 TestFlight 权限与导出路径冒烟测试仍是重要补充验证，应在审核期间尽快完成。

本轮针对 2.4.5 Hardware Compatibility，重点检查了：无蓝牙设备启动、权限拒绝、截图/录屏导出、沙盒路径、安全书签、系统设置页、隐私入口、出口合规、崩溃点、日志敏感信息、签名和资源。

## 已修复

1. **截图、录屏和快剪导出目录统一使用用户选择目录的安全书签。** 不再把沙盒容器内的伪“下载目录”展示为用户可访问路径；重启后仍解析同一授权目录。
2. **自定义编辑器路径使用安全书签。** 重启或沙盒权限收回时不再依赖失效的裸路径。
3. **系统“设置”窗口不再显示三个占位页。** `⌘,` 现在复用完整设置界面。
4. **蓝牙试验功能保持关闭且无用户入口。** App Store 权限、Info.plist 和线上隐私政策均不再声明蓝牙。
5. **补齐出口合规声明。** 最终 Info.plist 固定写入 `ITSAppUsesNonExemptEncryption=false`，避免每个新构建再次显示“缺少出口合规证明”。
6. **应用内补齐隐私政策和问题反馈入口。** 隐私政策指向 Cloudflare Pages；反馈指向 GitHub Issues，可附截图和日志。
7. **隐私政策已同步线上版本。** 删除不再使用的蓝牙权限说明，保留屏幕录制、麦克风、本地数据和可选 AI 说明。
8. **日志脱敏。** 不再记录便签正文、标题、完整本地路径、自定义 AI 地址或服务端响应正文。
9. **消除一组实际运行路径的崩溃点。** 包括屏幕编号强制转换、录屏音轨格式强制转换、空绘图元素、不可用屏幕和 ScreenCaptureKit 新增输出类型。
10. **清理 SwiftPM 非资源文件告警。** 设计文档、备份和 ini 文件不再被当成未处理资源。

## 提审前必须人工验证（P0）

使用干净 macOS 用户、TestFlight，或另一台未授权过 Quite Note 的 Mac；不要覆盖当前生产数据。

1. 首次启动不主动弹蓝牙、屏幕录制、麦克风或辅助功能授权，也不自动跳系统设置。
2. 点击截图后，拒绝屏幕录制权限：App 不崩溃、不假死，出现可退出的权限说明。
3. 允许屏幕录制后截图；首次保存选择真实目录。界面显示、复制到剪贴板的路径和 Finder 中实际文件完全一致。
4. 退出并重启 App，再次截图，仍写入同一目录；如书签失效，应重新让用户选目录，不得静默写入容器路径。
5. 区域录屏与快剪各导出一次，重复第 3、4 项路径验证；记录卡片只展示可理解的文件名/视频信息，不展示容器路径。
6. 开启麦克风录屏后拒绝麦克风权限：应降级或提示，不得崩溃。
7. `⌘,` 打开完整设置；隐私政策和问题反馈链接均可打开。
8. 全程确认没有蓝牙入口或蓝牙授权弹窗。

## 已发现但不阻断本次构建的问题

### P1：国际化尚未完成

当前已具备按系统语言加载中英文资源的基础设施，但静态扫描仍发现约 262 处直接写在 SwiftUI 中的中文文案，分布在约 32 个文件。因此：

- 中国大陆/中文系统体验可继续提审；
- 若要承诺完整英文体验并全球推广，应先完成全界面字符串抽取、英文翻译和英文系统冒烟测试；
- 商店元数据不得声称已经完整支持英文，直到这项完成。

### P1：长截图模块是隐藏的半成品

模块目前只采集多帧并返回最后一帧，没有执行拼接。扫描确认正式工具栏、菜单和快捷键没有调用入口，审核员无法触发，所以暂不阻断本次提交。后续只有完成拼接、保存和失败降级测试后才能重新开放入口。

### P2：Swift 6 并发兼容告警

当前 Swift 5.9 / Swift 5 语言模式可正常构建，但录屏锁、Core Data 闭包、AVVideoCompositing 和通知回调存在 Swift 6 严格并发告警。它们不是当前 App Store 拒审项，但升级 Swift 6 前必须集中处理。

### P2：隐私清单

当前包没有 `PrivacyInfo.xcprivacy`。现有上传链路未因此被 Apple 拒绝，扫描也未把它判定为本次硬阻塞；建议在完成 Required Reason API 盘点后补充，而不是复制一个未经核对的模板。

### P2：少量防御性强制解包

剩余强制解包主要位于“系统必然存在 Application Support 目录”“GUI 进程必然至少有一个屏幕”及 SwiftUI Preview。它们不是本次拒审的高概率原因，后续可做统一安全化。
